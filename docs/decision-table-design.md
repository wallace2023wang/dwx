## 1. 核心概念

**决策表 = 用 Excel 表格写规则**，适合多条件、多结果、枚举型业务（如风险等级、利率定价）。



* 每一行 = 一条规则

* 每一列 = BOM 的一个字段（条件列或动作列）

* 空单元格 = 通配（任意值都命中）

* 执行时按行顺序或命中策略，所有命中行都执行（COLLECT）



***

## 2. 决策表结构（以 "风险等级评估" 为例）

### 2.1 列分组



```

│ 借款申请人              │ 贷款申请                │ 贷款决定                  │

├──────┬──────┬──────────┼──────────┬───────────────┼──────────┬──────────────────┤

│ 年龄 │ 信用分│ 逾期次数 │ 金额(万) │ 期限(月)      │ 风险等级 │ 建议动作         │

├──────┼──────┼──────────┼──────────┼───────────────┼──────────┼──────────────────┤

│      │      │          │          │               │ 低       │ 自动通过         │  ← 行1

├──────┼──────┼──────────┼──────────┼───────────────┼──────────┼──────────────────┤

│      │>=700 │          │ <50      │               │ 低       │ 自动通过         │  ← 行2

├──────┼──────┼──────────┼──────────┼───────────────┼──────────┼──────────────────┤

│      │600..700│        │          │ <=36          │ 中       │ 标准审批         │  ← 行3

├──────┼──────┼──────────┼──────────┼───────────────┼──────────┼──────────────────┤

│      │<600  │ >=1      │          │               │ 高       │ 人工复核         │  ← 行4

│<18   │      │          │          │               │ 拒绝     │ 拒绝             │  ← 行5

└──────┴──────┴──────────┴──────────┴───────────────┴──────────┴──────────────────┘
```

### 2.2 单元格语法



| 字段类型    | 写法               | 含义        |
| ------- | ---------------- | --------- |
| number  | `600..700`       | 区间（含两端）   |
| number  | `[600,700)` / `(600,700]` | 可配置开闭边界 |
| number  | `>=700` / `<50`  | 比较        |
| number  | `600`            | 等于 600    |
| enum    | `低,中`            | 枚举值任意一个命中 |
| string  | `包含"逾期"`         | 字符串操作     |
| boolean | `true` / `false` | 布尔        |
| 空       | （留空）             | 通配，任意值都命中 |

### 3.2 关键交互



* **类 Excel 网格**：点击单元格直接编辑，Tab 跳下一单元格，Enter 跳下一行

* **列头**：两级（事实类型分组 / 字段名），蓝色虚线下划线（业务术语）

* **列头右键菜单**：删除列 / 改列类型（条件↔动作）/ 冻结列

* **行号列**：最左固定，显示序号，右键插入 / 删除 / 复制行

* **空单元格**：浅灰底，hover 提示 "留空 = 通配"

* **类型不匹配**：数字列里写了字符串，单元格红底

* **枚举值**：点击单元格弹出下拉，只能选 BOM 里定义的枚举值

* **值校验**：`600..abc` 这种非法表达式红框提示

## 4. 和 BOM 的联动（核心）

### 4.1 列从 BOM 生成



* 点 "+ 添加条件列"→ 弹出对话框，列出 BOM 所有 factType + 所有 fields（排除已经在表里的）

* 选 "借款申请人。信用分"→ 自动加一列，列头显示 "信用分"，数据类型 number

* 单元格输入自动按 number 校验

### 4.2 字段类型决定单元格行为



| BOM 字段类型            | 单元格编辑器                | 校验           |
| ------------------- | --------------------- | ------------ |
| number / bigdecimal | 文本输入，接受 `>=` `<` `..` | 必须是数字或区间     |
| enum                | 下拉选择（多选时逗号分隔）         | 只能选 BOM 定义的值 |
| boolean             | 下拉 true/false         | 二选一          |
| string              | 文本输入，支持 `包含"x"`       | 无强校验         |
| date                | 日期选择器                 | 日期格式         |

### 4.3 BOM 变更影响



| BOM 变化             | 决策表反应            |
| ------------------ | ---------------- |
| 删除字段               | 该列整列标红，禁止保存      |
| 字段类型 number→string | 列头提示类型变更，已有数据值标红 |
| 枚举值删除              | 单元格里用了被删枚举值的标红   |
| 字段 label 修改        | 列头显示名自动更新        |
| 删除 factType        | 引用该类型的所有列标红      |

## 5. 冲突与覆盖检测

决策表的核心痛点是**行之间的逻辑重叠**，编辑器必须实时检测：

### 5.1 检测规则



* **未命中行**：某行条件比上面某行更窄，但结果不同 —— 比如行 3 写 "600..700→中"，行 4 写 "<600, 逾期>=1→高"，如果有人 650 分且逾期 2 次，两行都命中

* **永远不会命中的行**：被上面行完全覆盖 —— 行 5"<18→拒绝"，如果行 1 是空（全通配→低），那行 5 永远不会先命中（COLLECT 模式下都执行，但 FIRST 模式下行 5 永远不触发）

* **矛盾行**：条件重叠但结果冲突 —— 两行都命中了同一客户，一个说 "通过" 一个说 "拒绝"

### 5.2 UI 提示



* 行号旁出小三角警告图标

* 底部 "未命中警告" 面板列出问题行

* hover 警告图标显示详情："行 5 被行 1 通配覆盖，FIRST 策略下不会执行"

当前实现做静态分析并在试运行时返回实际命中轨迹。诊断分为错误、警告和提示，覆盖重复、动作冲突、不可达、条件域为空、全空通配、普通重叠、缺口与分析能力限制。

## 6. 命中策略与执行

在 Ruleset 配置里全局设置，决策表本身不重复：



| 策略       | 行为                |
| -------- | ----------------- |
| COLLECT  | 所有命中行都执行，动作累加（推荐） |
| FIRST    | 第一行命中就停，下面不跑      |
| PRIORITY | 按行优先级排序，高优先级先跑    |

决策表**不支持行级 salience**（MVP），整表一个命中策略。

## 7. 存储格式

决策表存结构化 JSON，不是 CSV：



```
{

&#x20; "name": "风险等级评估",

&#x20; "type": "decision-table",

&#x20; "hitPolicy": "COLLECT",

&#x20; "columns": \[

&#x20;   {"factType": "Borrower", "field": "age", "kind": "condition"},

&#x20;   {"factType": "Borrower", "field": "creditScore", "kind": "condition"},

&#x20;   {"factType": "Borrower", "field": "delinquencies", "kind": "condition"},

&#x20;   {"factType": "Loan", "field": "amount", "kind": "condition"},

&#x20;   {"factType": "Loan", "field": "durationMonths", "kind": "condition"},

&#x20;   {"factType": "LoanDecision", "field": "riskLevel", "kind": "action"},

&#x20;   {"factType": "LoanDecision", "field": "needsManualReview", "kind": "action"}

&#x20; ],

&#x20; "rows": \[

&#x20;   {"cells": \["", "", "", "", "", "低", "false"]},

&#x20;   {"cells": \["", ">=700", "", "<500000", "", "低", "false"]},

&#x20;   {"cells": \["", "600..700", "", "", "<=36", "中", "false"]},

&#x20;   {"cells": \["", "<600", ">=1", "", "", "高", "true"]},

&#x20;   {"cells": \["<18", "", "", "", "", "拒绝", "false"]}

&#x20; ]

}
```

## 8. 编译链路（决策表 JSON → DRL）

每一行编译成一条独立规则：



```
行3: \["", "600..700", "", "", "<=36", "中", "false"]
```

→



```
rule "风险等级评估\_row3"

&#x20; when

&#x20;   \$b : Borrower(creditScore >= 600 && creditScore <= 700)

&#x20;   \$l : Loan(durationMonths <= 36)

&#x20;   \$d : LoanDecision()

&#x20; then

&#x20;   modify(\$d) { setRiskLevel("中"), setNeedsManualReview(false) };

end
```

空单元格不生成 when 条件（通配）。
