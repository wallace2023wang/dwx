# CEP 事件流可视化编辑器需求设计

版本：v1.0  
状态：开发基线  
更新日期：2026-10-01  
关联：`dual-engine-architecture-design.md`、`cep-time-driven-statement-support.md`、`bom-editor-design.md`

## 1. 背景与产品原则

EventStream 当前以 Esper EPL 为运行语言。EPL 适合引擎开发人员，但窗口、聚合、事件模式和处理时间语义对普通业务用户不友好。Decision Workbench 的目标不是把 SQL 文本框搬到浏览器，而是让业务人员使用 BOM 词汇配置事件检测规则，由平台生成和校验 EPL。

编辑器遵循以下原则：

1. **向导式编辑是默认主视图**。新建事件流和新建检测语句默认进入向导，不要求用户理解 EPL。
2. **高级 EPL 是次级能力**。仅供熟悉 Esper 的规则开发人员处理模板暂不覆盖的场景。
3. **BOM 驱动控件**。事件源、字段、数据类型、分组字段和可用操作符来自当前 BOM/Event Profile。
4. **生成 EPL 可见但默认只读**。业务用户可以审阅实际运行内容，但不会误改生成结果。
5. **不伪造双向转换**。历史 EPL 或高级 EPL 无法可靠解析回模板参数时，继续显示为高级模式，不猜测、不丢失语义。
6. **发布内容仍是 EPL 快照**。向导只改变创作体验，不改变 Esper 编译、Release checksum 和 Runtime 执行边界。

## 3. 信息架构

编辑器保持三栏工作区：

| 区域 | 内容 | 主要用户 |
|---|---|---|
| 左栏 | EventStream 资产、检测语句列表、启停、删除、新建 | 全部用户 |
| 中栏 | 向导参数表单；高级模式时为 EPL 编辑器 | 业务作者 / 开发人员 |
| 右栏 | 生成 EPL 只读预览、中文语义摘要、时间语义提示 | 全部用户 |

页面顶部保留保存、编译、保存并新建测试、发布和删除资产。删除使用垃圾桶图标并提供 tooltip，不占用主操作文案。

## 4. 默认创作流程

### 4.1 新建 EventStream

1. 用户点击“新建”。
2. 系统基于 BOM 的第一个输入 Event Type 创建一条 `single-threshold` 语句。
3. 系统选择第一个数值字段；没有数值字段时选择第一个可检测字段。
4. 中栏直接显示向导表单，默认值包括事件源、检测字段、操作符和阈值。
5. 右栏实时显示生成 EPL，EPL 不可直接编辑。

默认草稿等价于：

```ts
{
  name: '传感器异常检测',
  statements: [{
    name: 'SingleThreshold1',
    label: '单点阈值',
    enabled: true,
    mode: 'guided',
    template: 'single-threshold',
    params: { eventType, field, operator: '>=', value: 25 },
    epl: generatedEpl
  }]
}
```

如果 BOM 尚未加载完成，“新建”按钮不可用。CEP 项目没有有效 Event Type 时，应先引导用户完成 BOM，而不是创建不可编译的占位 EPL。

### 4.2 新建检测语句

主入口为“从向导新建”，展示模板名称和业务说明。高级 EPL 使用独立代码图标入口，并显示“高级 EPL”tooltip。

新建后自动选中该语句。语句 ID 必须是英文标识符；中文检测名用于资产列表、测试报告和命中轨迹。

### 4.3 向导与高级模式切换

- `guided -> advanced`：保留当前生成 EPL。用户明确进入高级模式后才允许修改文本。
- 高级文本一旦偏离模板生成结果，保存或重新生成前必须选择“保留高级 EPL”或“覆盖为模板生成”。
- 选择“保留高级 EPL”后移除 `template/params`，该语句成为纯高级语句。
- `advanced -> guided`：只有仍保留模板元数据且 EPL 未偏离时才能直接恢复；纯 EPL 不自动反向解析。
- 历史数据没有 `mode/template/params` 时按高级 EPL 打开，运行语义保持不变。

### 4.4 保存、编译、测试与发布

- **保存**：先调用真实 Esper 编译当前草稿，编译通过后保存并显示新 revision。
- **编译**：只校验当前未保存草稿，不改变 revision，成功后明确显示“编译通过”。
- **保存并新建测试**：保存草稿并创建测试套件骨架；允许目标尚未发布，以支持先准备测试数据和断言。
- **保存并发布**：保存草稿后生成新的 EventStream 资产版本，不等同于创建或部署 Release。
- 草稿阶段创建的测试套件显示“待目标发布”，不能运行，也不参与 Release 门禁；目标发布后自动解析到最新已发布版本，才允许运行。
- 组合操作必须显示端到端处理中状态和最终结果，不得只显示内部编译步骤成功。

## 5. 模板能力

### 5.1 已支持模板

| 模板 | 业务语义 | 主要参数 |
|---|---|---|
| 单点阈值 | 单条事件字段满足比较条件 | 事件源、字段、操作符、阈值 |
| 窗口均值 | 窗口内字段均值满足条件 | 窗口、分组、字段、操作符、阈值 |
| 窗口波动 | 窗口内最大值与最小值差超限 | 窗口、分组、字段、差值 |
| 事件计数 | 窗口内事件数量达到阈值 | 窗口、分组、次数 |
| 窗口求和 | 窗口内字段合计达到阈值 | 窗口、分组、字段、阈值 |

窗口模板支持：

- 滑动窗口：`#time(n)`。
- 跳跃窗口：`#time_batch(n)`。
- 时间单位：秒、分钟、小时。
- 当前均使用 Esper 处理时间；右栏必须常驻提示，不得暗示按业务 `eventTime` 回放。

### 5.2 后续模板优先级

| 优先级 | 模板 | 说明 |
|---|---|---|
| P1 | 缺席检测 | 指定时间内未收到某事件，依赖 `pattern + timer` |
| P1 | 双事件时序 | A 后在限定时间内出现 B，支持 followed-by |
| P1 | 连续次数 | 连续 N 次满足条件，不等价于普通窗口计数 |
| P1 | 周期触发 | 每隔 N 秒/分钟产生巡检事件 |
| P2 | 状态迁移 | 事件和当前状态共同决定下一状态 |
| P2 | 多流关联 | 两类事件按业务键和时间范围关联 |

每个模板开放 UI 前，必须通过真实 Esper 8.8.0 编译和样例执行基线，不能只验证字符串生成。

## 6. 类型与控件联动

向导字段来自选中 Event Type，包括事件信封字段和 BOM 业务字段。控件由字段类型决定：

| 类型 | 可用比较 | 值控件 |
|---|---|---|
| Integer / Decimal | `=` `!=` `>` `>=` `<` `<=` | number input |
| Boolean | `=` `!=` | true/false 选择 |
| Enum | `=` `!=` | BOM 枚举下拉 |
| String | `=` `!=` | 文本输入 |
| Date | 本期仅高级 EPL | 后续日期/时间控件 |
| List<String> | 本期仅高级 EPL | 后续多值控件 |

窗口均值、窗口波动和窗口求和只允许数值字段。分组字段优先推荐 `eventKey`、`warehouseId`、`sensorId`、`source`。

## 7. 数据模型与一致性

```ts
interface EplStatement {
  name: string
  label?: string
  description?: string
  enabled: boolean
  mode: 'guided' | 'advanced'
  template?: CepTemplateId
  params?: Record<string, unknown>
  epl: string
}
```

向导语句中，`template + params` 是创作事实来源，`epl` 是可编译缓存和发布产物。高级语句中，`epl` 是事实来源。

前端实时生成 EPL；服务端保存时应使用共享模板生成器重新生成或校验 EPL 一致性，防止绕过浏览器提交互相矛盾的 `params/epl`。该服务端一致性校验列为 P1，现阶段前端保存前执行冲突确认。

模板元信息不进入 Runtime module checksum；实际 `schemas + enabled EPL statements` 决定运行制品 checksum。作者修改中文标签但不改变 EPL 时，不应产生不同运行制品。

## 8. 删除语义

### 8.1 删除 EventStream 资产

端点：

```http
DELETE /api/projects/:projectId/event-streams/:eventStreamId
Content-Type: application/json

{ "revision": 4 }
```

规则：

- 删除是软删除，设置 `archived=true`，不物理清除版本历史。
- 必须提供当前 revision；过期 revision 返回 `409` 和当前修订信息。
- 资产处于已提交变更集时返回 `409`，不能绕过审核锁。
- 删除已发布资产时必须二次确认并显示已发布版本。
- 既有 Release 是不可变制品，删除资产不影响其部署、执行和审计。
- 删除后不能再以该资产创建新 Release，资产列表和普通详情不再返回它。
- 记录 `asset.archive` 审计事件，包含删除人、修订号和最后发布版本。

后续恢复功能使用独立端点，不允许通过创建同 ID 资产恢复。

### 8.2 删除检测语句

- 删除只修改当前草稿，用户保存后生效。
- 必须二次确认，文案显示中文检测名。
- EventStream 至少保留一条语句，最后一条不能删除。
- 删除派生事件生产语句后，如果其他语句仍引用其输出，保存/编译必须失败并指出引用语句。
- 已发布版本和既有 Release 不受草稿语句删除影响。

## 9. 校验与错误反馈

- 参数输入即时进行必填、标识符、数值和 BOM 字段校验。
- “保存”先执行真实 Esper 编译，再持久化草稿。
- 编译错误应关联到语句 ID；高级 EPL 后续增加行列定位。
- 禁用语句保留在草稿和版本作者信息中，但不进入 Runtime module。
- EventStream 最多 100 条语句；达到上限时禁用新建入口并说明原因。
- 模板参数和 EPL 不一致时禁止静默保存。

## 10. 权限与治理

- 查看者只能查看向导参数和 EPL 预览。
- 作者可使用向导、保存、编译和提交审核。
- 是否允许高级 EPL 应支持项目级权限开关；默认仅规则开发人员和管理员可用。
- 删除资产沿用资产编辑权限、审核锁和审计要求。
- 发布仍受变更集、测试门禁和 Release 权限控制，向导模式不降低治理要求。
