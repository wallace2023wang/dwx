# CEP 事件流可视化编辑器需求设计

版本：v1.1

状态：开发基线

更新日期：2026-10-08

关联：`dual-engine-architecture-design.md`、`cep-time-driven-statement-support.md`、`bom-editor-design.md`

本次更新：为每条 EPL 检测语句增加独立“业务说明”窗口，明确它与事件流总体说明、自动语义摘要和 EPL 代码注释的边界。

## 1. 背景与产品原则

EventStream 当前以 Esper EPL 为运行语言。EPL 适合引擎开发人员，但窗口、聚合、事件模式和处理时间语义对普通业务用户不友好。DWX 的目标不是把 SQL 文本框搬到浏览器，而是让业务人员使用 BOM 词汇配置事件检测规则，由平台生成和校验 EPL。

编辑器遵循以下原则：

1. **向导式编辑是默认主视图**。新建事件流和新建检测语句默认进入向导，不要求用户理解 EPL。
2. **高级 EPL 是次级能力**。仅供熟悉 Esper 的规则开发人员处理模板暂不覆盖的场景。
3. **BOM 驱动控件**。事件源、字段、数据类型、分组字段和可用操作符来自当前 BOM/Event Profile。
4. **生成 EPL 可见但默认只读**。业务用户可以审阅实际运行内容，但不会误改生成结果。
5. **不伪造双向转换**。历史 EPL 或高级 EPL 无法可靠解析回模板参数时，继续显示为高级模式，不猜测、不丢失语义。
6. **发布内容仍是 EPL 快照**。向导只改变创作体验，不改变 Esper 编译、Release checksum 和 Runtime 执行边界。

## 2. 范围

### 2.1 本期范围

- EventStream 资产软删除。
- 语句新增、启停和删除。
- 新建 EventStream 默认包含一条“单点阈值”向导语句。
- 新建语句优先从业务模板创建。
- 每条检测语句提供独立业务说明窗口，向导和高级 EPL 模式均可编辑。
- 检测语句支持业务分组、拖动排序和键盘重排。

- 显式切换到高级 EPL，保留模板冲突确认。
- 保存、编译、发布和生成测试骨架继续复用现有链路。

## 3. 信息架构

编辑器保持三栏工作区：

| 区域 | 内容 | 主要用户 |
|---|---|---|
| 左栏 | EventStream 资产、检测语句列表、启停、删除、新建 | 全部用户 |
| 中栏 | 语句分组、业务说明；向导参数表单或高级 EPL 编辑器 | 业务作者 / 开发人员 |
| 右栏 | 生成 EPL 只读预览、自动语义摘要、时间语义提示 | 全部用户 |

页面顶部保留保存、编译、保存并新建测试、发布和删除资产。删除使用垃圾桶图标并提供 tooltip，不占用主操作文案。

页面顶部 EventStream 级文本框命名为“事件流说明”，用于描述整条事件流的业务目标和输入输出范围；选中语句后，中栏提供“业务说明”，只描述当前 EPL 语句。两者不得继续使用含义模糊的“说明”占位文本。

颜色只表达单一语义：蓝色表示当前选择和主操作，绿色表示已发布或编译通过，橙色表示草稿和未保存修改，红色表示编译失败或危险操作，灰色表示未校验及中性信息。资产选中态不得替代生命周期状态；列表和编辑器标题区必须分别显示草稿/已发布、发布后草稿有修改、本地未保存和编译结果。

## 4. 默认创作流程

### 4.1 新建 EventStream

1. 用户点击“新建”。
2. 系统基于 BOM 的第一个输入 Event Type 创建一条 `single-threshold` 语句。
3. 系统选择第一个数值字段；没有数值字段时选择第一个可检测字段。
4. 中栏直接显示向导表单，默认值包括事件源、检测字段、操作符和阈值。
5. 右栏实时显示生成 EPL，EPL 不可直接编辑。

默认草稿等价于：

```ts
{
  name: '传感器异常检测',
  statements: [{
    name: 'SingleThreshold1',
    label: '单点阈值',
    enabled: true,
    mode: 'guided',
    template: 'single-threshold',
    params: { eventType, field, operator: '>=', value: 25 },
    epl: generatedEpl
  }]
}
```

如果 BOM 尚未加载完成，“新建”按钮不可用。CEP 项目没有有效 Event Type 时，应先引导用户完成 BOM，而不是创建不可编译的占位 EPL。

### 4.2 新建检测语句

主入口为“从向导新建”，展示模板名称和业务说明。高级 EPL 使用独立代码图标入口，并显示“高级 EPL”tooltip。

新建后自动选中该语句。语句 ID 必须是英文标识符；中文检测名用于资产列表、测试报告和命中轨迹。

### 4.3 向导与高级模式切换

- `guided -> advanced`：保留当前生成 EPL。用户明确进入高级模式后才允许修改文本。
- 高级文本一旦偏离模板生成结果，保存或重新生成前必须选择“保留高级 EPL”或“覆盖为模板生成”。
- 选择“保留高级 EPL”后移除 `template/params`，该语句成为纯高级语句。
- `advanced -> guided`：只有仍保留模板元数据且 EPL 未偏离时才能直接恢复；纯 EPL 不自动反向解析。
- 历史数据没有 `mode/template/params` 时按高级 EPL 打开，运行语义保持不变。

### 4.4 语句业务说明窗口

#### 4.4.1 产品目标

业务说明用于回答“这条语句为什么存在、检测什么、命中后产生什么业务结果”，使审核人、测试人员和运维人员不阅读 EPL 也能理解其用途。它不是 EPL 代码的一部分，也不承担记录实现细节的职责。

编辑器同时展示四类信息，边界如下：

| 信息 | 作用 | 是否持久化 | 是否参与编译 / checksum |
|---|---|---|---|
| 事件流说明 | 描述整个 EventStream 的业务目标和边界 | `draft.description` | 否 |
| 语句业务说明 | 描述当前检测语句的业务用途 | `statements[].description` | 否 |
| 自动语义摘要 | 根据模板参数即时解释当前条件、窗口和输出 | 不持久化，由前端计算 | 否 |
| EPL 注释 | 开发人员记录实现细节，可使用中文 `//` 或 `/* */` | 作为 EPL 文本的一部分 | 是 |

业务说明不得自动拼接为 EPL 注释。否则仅修改说明也会改变运行制品 checksum，并造成无意义的重新发布。

#### 4.4.2 布局与控件

- 业务说明窗口放在中栏“语句分组”下方、向导参数或高级 EPL 编辑器上方，切换模式时位置不变。
- 标题固定为“业务说明”，显示 `已输入字数 / 500`，使用最小 3 行、可纵向拉伸的多行文本框。
- 占位提示为“说明该语句检测什么、适用场景以及命中后的业务结果”。
- 右栏保留只读“自动语义摘要”，不再把 `description` 当作自动摘要展示；业务说明为空时不得用自动摘要冒充已填写内容。
- 左侧语句列表在名称下方最多显示一行说明摘要；为空时不占额外高度，完整内容通过选中语句查看。
- 页面顶部原“说明”文本框增加“事件流说明”标签和 500 字计数，避免与语句级说明混淆。

推荐布局：

```text
中栏
├─ 语句分组
├─ 业务说明（0 / 500）
│  └─ 多行文本框
└─ 模板参数表单 / 高级 EPL 编辑器

右栏
├─ EPL 预览
├─ 自动语义摘要（只读）
└─ 时间语义提示
```

#### 4.4.3 默认值与编辑规则

- 新建向导语句时，业务说明默认为空；自动语义摘要单独显示模板生成结果。
- 提供次级操作“按当前配置生成说明”，将自动语义摘要复制到业务说明，供作者继续修改。
- 业务说明非空时再次生成必须二次确认，禁止静默覆盖人工内容。
- 修改模板参数、切换向导/高级模式、重新生成 EPL 时，不得改写已有业务说明。
- 新建高级 EPL 语句的业务说明同样默认为空，并可独立编辑。
- 允许中文、英文、数字和常用标点，前后空白在保存时裁剪，最大 500 个字符；换行计入字符数。
- 业务说明暂不设为保存必填项，避免阻塞历史资产修订；保存为空时显示非阻断提示“建议补充业务说明”。

#### 4.4.4 兼容与治理

- 复用现有 `EplStatement.description`，不新增接口字段，不要求数据迁移。
- 历史语句已有 `description` 时原样展示，不判断它来自模板还是人工输入。
- 业务说明随草稿、资产版本和 Release 作者信息冻结，可用于变更对比、评审、项目知识资产报告和测试套件上下文。
- Runtime module 仍只包含运行所需的 schema、启用状态和 EPL；业务说明不得进入 Esper 部署模块。
- 仅修改事件流说明、业务说明、中文检测名或分组等作者信息时产生资产草稿修订和审计差异，但不得改变运行制品 checksum，也不要求重新编译才能保存。若用户执行“保存并发布”，发布链路仍按既有治理规则运行。
- 评审差异中将 `description` 显示为“业务说明”，同时展示修改前后文本，不与 EPL 差异混排。

### 4.5 保存、编译、测试与发布

- **保存**：EPL、语句 ID、启停或语句顺序等运行内容发生变化时，先调用真实 Esper 编译，编译通过后保存；仅修改事件流说明、语句业务说明、中文检测名或分组等作者元数据时直接保存并显示新 revision，不重复编译未变化的 EPL。
- **编译**：只校验当前未保存草稿，不改变 revision，成功后明确显示“编译通过”。
- **保存并新建测试**：保存草稿并创建测试套件骨架；允许目标尚未发布，以支持先准备测试数据和断言。
- **保存并发布**：保存草稿后生成新的 EventStream 资产版本，不等同于创建或部署 Release。
- 草稿阶段创建的测试套件显示“待目标发布”，不能运行，也不参与 Release 门禁；目标发布后自动解析到最新已发布版本，才允许运行。
- 组合操作必须显示端到端处理中状态和最终结果，不得只显示内部编译步骤成功。

## 5. 模板能力

### 5.1 已支持模板

| 模板 | 业务语义 | 主要参数 |
|---|---|---|
| 单点阈值 | 单条事件字段满足比较条件 | 事件源、字段、操作符、阈值 |
| 窗口均值 | 窗口内字段均值满足条件 | 窗口、分组、字段、操作符、阈值 |
| 窗口波动 | 窗口内最大值与最小值差超限 | 窗口、分组、字段、差值 |
| 事件计数 | 窗口内事件数量达到阈值 | 窗口、分组、次数 |
| 窗口求和 | 窗口内字段合计达到阈值 | 窗口、分组、字段、阈值 |
| 缺席检测 | 起始事件后规定时间内未收到后续事件 | 事件源、字段、操作符/阈值、关联键、等待时长、后续事件 |
| 双事件时序 | 起始事件后在时限内收到同键后续事件 | 事件源、字段、操作符/阈值、关联键、时限、后续事件 |
| 连续次数 | 同一关联键连续满足条件达到次数 | 事件源、字段、操作符/阈值、分组、次数 |
| 周期触发 | 按固定周期触发，不依赖输入事件 | 周期、时间单位 |
| 状态迁移 | 事件当前状态命中时输出目标状态 | 事件源、状态字段、当前状态、目标状态 |
| 多流关联 | 两类事件在同一时间窗口内按业务键关联 | 两类事件源、关联字段、窗口 |

窗口模板支持：

- 滑动窗口：`#time(n)`。
- 跳跃窗口：`#time_batch(n)`。
- 时间单位：秒、分钟、小时。
- 当前均使用 Esper 处理时间；右栏必须常驻提示，不得暗示按业务 `eventTime` 回放。

### 5.2 模板基线与后续

模板能力已全部交付（5 类窗口/阈值 + 6 类 pattern/timer）：

| 状态 | 模板 | 说明 |
|---|---|---|
| 已交付 | 缺席检测 | 指定时间内未收到某事件，依赖 `pattern + timer` |
| 已交付 | 双事件时序 | A 后在限定时间内出现 B，支持 followed-by |
| 已交付 | 连续次数 | 连续 N 次满足条件，不等价于普通窗口计数 |
| 已交付 | 周期触发 | 每隔 N 秒/分钟产生巡检事件 |
| 已交付 | 状态迁移 | 事件状态字段等于当前状态时输出目标状态（`select *, '<next>' as nextState`） |
| 已交付 | 多流关联 | 两类事件在同一 `#time` 窗口内按业务键配对 |

新增或修改模板时必须同步更新 `test/fixtures/cep-template-baseline.json`：每个模板开放 UI 前必须通过真实 Esper 8.8.0 编译和样例执行基线，不能只验证字符串生成。前端 `frontend/src/lib/cepTemplates.ts` 与共享 `shared/cep-templates.js` 必须生成完全一致的 EPL，服务端按共享生成器重新计算并拒绝漂移。

## 6. 类型与控件联动

向导字段来自选中 Event Type，包括事件信封字段和 BOM 业务字段。控件由字段类型决定：

| 类型 | 可用比较 | 值控件 |
|---|---|---|
| Integer / Decimal | `=` `!=` `>` `>=` `<` `<=` | number input |
| Boolean | `=` `!=` | true/false 选择 |
| Enum | `=` `!=` | BOM 枚举下拉 |
| String | `=` `!=` | 文本输入 |
| Date | 本期仅高级 EPL | 后续日期/时间控件 |
| List<String> | 本期仅高级 EPL | 后续多值控件 |

窗口均值、窗口波动和窗口求和只允许数值字段。分组字段优先推荐 `eventKey`、`warehouseId`、`sensorId`、`source`。

## 7. 数据模型与一致性

```ts
interface EplStatement {
  name: string
  label?: string
  description?: string
  group?: string
  enabled: boolean
  mode: 'guided' | 'advanced'
  template?: CepTemplateId
  params?: Record<string, unknown>
  epl: string
}

type CepOutputField =
  | { alias: string; source: 'field'; field: string }
  | { alias: string; source: 'constant'; value: string | number | boolean }
```

向导语句中，`template + params` 是创作事实来源，`epl` 是可编译缓存和发布产物。高级语句中，`epl` 是事实来源。

前端实时生成 EPL；服务端保存时使用共享模板生成器重新生成并校验 EPL 一致性，防止绕过浏览器提交互相矛盾的 `params/epl`。

`group` 是作者侧目录元数据，不进入 Runtime module checksum。`statements[]` 的数组顺序是实际编译与执行顺序；拖动和上下移动直接调整数组，不由分组名称隐式重排。分组名称最长 80 字，空值归入“未分组”。

`description` 是作者维护的语句级业务说明。模板的自动语义摘要由 `describeCepTemplate(template, params)` 在展示时计算，不能在每次参数变化时回写或覆盖 `description`。已有数据继续兼容读取；新建语句不再把自动摘要直接作为持久化业务说明。

`single-threshold.params.outputFields` 为空时继续生成 `select *`，兼容已有资产。配置输出映射后，源字段生成 `<field> as <alias>`，固定值生成 `<literal> as <alias>`；字段名和别名必须是英文标识符，别名不得重复。窗口聚合模板暂不开放自定义输出，避免引入不合法的非聚合字段。

模板元信息不进入 Runtime module checksum；实际 `schemas + enabled EPL statements` 决定运行制品 checksum。作者修改中文标签但不改变 EPL 时，不应产生不同运行制品。

## 8. 删除语义

### 8.1 删除 EventStream 资产

端点：

```http
DELETE /api/projects/:projectId/event-streams/:eventStreamId
Content-Type: application/json

{ "revision": 4 }
```

规则：

- 删除是软删除，设置 `archived=true`，不物理清除版本历史。
- 必须提供当前 revision；过期 revision 返回 `409` 和当前修订信息。
- 资产处于已提交变更集时返回 `409`，不能绕过审核锁。
- 删除已发布资产时必须二次确认并显示已发布版本。
- 既有 Release 是不可变制品，删除资产不影响其部署、执行和审计。
- 删除后不能再以该资产创建新 Release，资产列表和普通详情不再返回它。
- 记录 `asset.archive` 审计事件，包含删除人、修订号和最后发布版本。

后续恢复功能使用独立端点，不允许通过创建同 ID 资产恢复。

### 8.2 删除检测语句

- 删除只修改当前草稿，用户保存后生效。
- 必须二次确认，文案显示中文检测名。
- EventStream 至少保留一条语句，最后一条不能删除。
- 删除派生事件生产语句后，如果其他语句仍引用其输出，保存/编译必须失败并指出引用语句。
- 已发布版本和既有 Release 不受草稿语句删除影响。

## 9. 校验与错误反馈

- 参数输入即时进行必填、标识符、数值和 BOM 字段校验。
- 事件流说明和语句业务说明分别校验，均不得超过 500 个字符；超限时在字段下方即时提示，并禁用保存、发布和创建测试。
- “保存”在运行内容变化时先执行真实 Esper 编译；仅作者元数据变化时可直接持久化草稿。
- 编译错误关联语句 ID，并显示 Esper 返回的行列定位。
- 禁用语句保留在草稿和版本作者信息中，但不进入 Runtime module。
- EventStream 最多 100 条语句；达到上限时禁用新建入口并说明原因。
- 模板参数和 EPL 不一致时禁止静默保存。

## 10. 权限与治理

- 查看者只能查看向导参数和 EPL 预览。
- 作者可使用向导、保存、编译和提交审核。
- 是否允许高级 EPL 应支持项目级权限开关；默认仅规则开发人员和管理员可用。
- 删除资产沿用资产编辑权限、审核锁和审计要求。
- 发布仍受变更集、测试门禁和 Release 权限控制，向导模式不降低治理要求。
