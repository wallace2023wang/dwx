# 交付任务拆分

版本：0.10  
更新日期：2026-09-29

## 里程碑总览

| 里程碑 | 目标 | 完成标准 |
|---|---|---|
| M1 发布执行闭环 | 三产品边界真实落地 | Release 可创建、部署到独立 RES 并执行 |
| M2 决策资产可用 | 决策表和规则流满足常用业务场景 | 命中策略、分支、映射、批量测试可用 |
| M3 团队治理 | 支持多人协作和受控发布 | 登录、RBAC、变更集、审批、审计可用 |
| M4 企业运行 | 可用于受控生产流量 | 灰度、回滚、监控、限流、高可用可用 |

### M2.2 规则流

- [x] 线性步骤、版本冻结、顺序执行和执行轨迹。
- [x] 公共步骤后的单个排他条件网关、首条匹配语义和默认分支。
- [x] 分支路径冻结到 Release `routing`，并由 Team Server 与 RES 一致执行、验签和返回网关轨迹。
- [x] 节点输入输出映射、类型与方向校验、Release 冻结和执行轨迹。
- [x] 项目级 Web 编排工作区：真实规则流读取、新建、步骤排序、排他/默认分支、字段映射、实时 React Flow 画布、乐观锁保存、Drools 校验、发布及 Release 目标选择。
- [x] 依赖资产升版后标记规则流需要重新发布，并提示多个步骤写同一输出字段的顺序覆盖风险。
- [ ] 多级条件网关和任意图编排。
- [ ] 并行网关与聚合节点。
- [ ] 子流程、循环和循环依赖检测。

当前验收边界：一个流程可先执行公共步骤，再按显示顺序选择第一个满足条件的分支；无条件命中时进入唯一默认分支。支持最多 8 个分支和合计 20 个步骤，条件可读取输入或公共步骤输出。每个节点可在执行前后配置同类型字段映射，映射随资产版本和 Release 冻结，并在设计期与 RES 轨迹中返回实际复制值。分支顺序即业务优先级，尚不承诺并发、汇聚计算或嵌套网关语义。

## 任务依赖与执行顺序

```text
Release 模型
  -> Team Server Release API
  -> RES 部署与执行
  -> 发布中心 UI
  -> 端到端自动化测试
  -> 权限与审批门禁
  -> 灰度与生产治理

BOM/Vocabulary
  -> 结构化规则增强
  -> 决策表精确分析
  -> RES 去除硬编码事实字段
```

## 当前优先级调整

近期按以下顺序推进：

1. 可配置审批、职责分离，以及批准 Change Set 到 Release 的强制门禁。
2. 草稿所有权、字段级冲突合并和协作会话。
3. 新旧版本并行对比、参数化数据集和覆盖率。
4. 多级网关、并行聚合和子流程。

XLSX/CSV 导入导出与导入差异预览已完成；后续只保留批量迁移模板和更细粒度差异合并优化。

每个里程碑必须先完成自动化验收，再开启依赖它的下一阶段。新增功能不能绕过 Release 直接向 RES 提交草稿 DRL。
