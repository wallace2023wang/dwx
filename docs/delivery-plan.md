# 交付任务拆分

版本：0.11
更新日期：2026-10-09

## 里程碑总览

| 里程碑 | 目标 | 完成标准 |
|---|---|---|
| M1 发布执行闭环 | 三产品边界真实落地 | Release 可创建、部署到独立 RES 并执行 |
| M2 决策资产可用 | 决策表和规则集满足常用业务场景 | 命中策略、分支、映射、批量测试可用 |
| M3 团队治理 | 支持多人协作和受控发布 | 登录、RBAC、变更集、审批、审计可用 |
| M4 企业运行 | 可用于受控生产流量 | 灰度、回滚、监控、限流、高可用可用 |

### M2.2 规则集

- [x] 线性步骤、版本冻结、顺序执行和执行轨迹。
- [x] 串行多级排他网关首版：网关可插入任一公共步骤边界，分支执行后汇合并继续后续公共主线，每个网关使用首条匹配和唯一默认分支语义。
- [x] 分支路径冻结到 Release `routing`，并由 Team Server 与 RES 一致执行、验签和返回网关轨迹。
- [x] 节点输入输出映射、类型与方向校验、Release 冻结和执行轨迹。
- [x] 项目级 Web 编排工作区：真实规则集读取、新建、步骤排序、排他/默认分支、字段映射、实时 React Flow 画布、乐观锁保存、Drools 校验、发布及 Release 目标选择。
- [x] 依赖资产升版后标记规则集需要重新发布，并提示多个步骤写同一输出字段的顺序覆盖风险。
- [x] 最多 4 个串行排他网关，新旧草稿和 Release 路由格式兼容，Team Server 与 RES 返回多网关 `paths` 轨迹。
- [x] 无环有向图首版：分支内可继续进入排他网关，多条路径可汇入同一后续步骤，草稿与 Release 分别使用 `graph` 和 `exclusive-dag`。
- [x] 并行网关与聚合节点首版：2–8 条分支基于同一事实快照隔离执行，全部汇入配对聚合节点；非冲突字段自动合并，同字段不同值明确失败。
- [x] 子流程首版：仅引用同项目已发布规则集，支持最多 4 层递归引用；发布父规则集时内联冻结子流程 DAG，保留来源轨迹，拒绝直接/间接循环、BOM 不一致和变量不兼容。
- [ ] 循环执行；当前继续拒绝循环、孤立节点、不可达节点和无效目标引用。
- [x] 节点级运行到此处、结构化失败定位和排他网关路径断言。

当前验收边界：旧线性模型继续支持最多 4 个串行排他网关；高级模式使用无环有向图，允许嵌套排他、任意汇合，以及最多 4 组配对的并行网关/聚合节点。每个并行网关包含 2–8 条分支，各分支从同一事实与变量快照隔离执行，聚合节点自动合并非冲突变化；多个分支对同一字段或变量写入不同值时返回冲突，不隐式采用后写覆盖。子流程引用同项目已发布规则集，最大嵌套深度 4，父规则集发布时内联冻结，因此旧父 Release 不依赖子 Release ID；子流程升版会提示父规则集重新发布。高级图最多 8 个排他网关，全流程展开后合计最多 20 个步骤。当前不支持嵌套并行和循环。

## 任务依赖与执行顺序

```text
Release 模型
  -> Team Server Release API
  -> RES 部署与执行
  -> 发布中心 UI
  -> 端到端自动化测试
  -> 权限与审批门禁
  -> 灰度与生产治理

BOM/Vocabulary
  -> 结构化规则增强
  -> 决策表精确分析
  -> RES 去除硬编码事实字段
```
