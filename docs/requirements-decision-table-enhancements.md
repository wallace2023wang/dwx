# 决策表增强需求（v0.2）

## 背景

当前决策表 MVP 已实现基础 Web 编辑：条件列/结果列增删、单元格按字段类型输入、行复制/排序/启停、试运行、发布编译。但与 传统规则平台 决策表相比，业务人员填表时遇到三个高频痛点。本次迭代补齐。

## 需求 1：条件范围与多值枚举

### 现状
每个条件单元格只能填一个单值，配合列头运算符（==, !=, >, >=, <, <=）形成原子条件。例如 `creditScore < 600`。

### 问题
- 想表达"信用评分在 600 到 700 之间"必须拆两行（>=600 和 <=700），或在一个单元格填不了。
- 想表达"客户类型是 黑名单 或 逾期"必须拆两行。

### 方案
扩展条件单元格的取值语法，列头运算符保持不变（作为外层比较），单元格内部支持：

| 语法 | 含义 | DRL 生成示例（列运算符 <） |
|---|---|---|
| `600` | 单值（现状） | `creditScore < 600` |
| `600..700` | 闭区间 | `creditScore >= 600 && creditScore <= 700` |
| `600..` | 左闭右开（>=600，无上界） | `creditScore >= 600` |
| `..700` | 左开右闭（<=700，无下界） | `creditScore <= 700` |
| `a,b,c` | 多值枚举（字符串） | `customerType in ("a","b","c")` |

规则：
- 区间语法 `..` 仅对 Integer/Double 类型生效；String/Boolean 字段报错。
- 多值逗号分隔仅对 String 类型生效；自动去掉每个值首尾空格，空段忽略。
- 列头运算符与单元格语法组合时：
  - 单值：运算符正常作用于该值。
  - 区间：忽略列头运算符，按区间语义生成 AND 条件。
  - 多值：仅当列头运算符为 `==` 时生成 `in`；列头为 `!=` 时生成 `not in`；其他运算符报错。
- 空单元格仍表示"本行不限制该列"（保持现状）。

### 校验
- 区间下界不得大于上界。
- 区间内数字必须符合字段类型范围（Integer 不溢出）。
- 多值枚举至少 1 个有效值，字符串长度 <=200。

## 需求 2：规则冲突检测

### 现状
两行启用行的条件可能同时被同一组 facts 满足，导致两条规则都触发、结果互相覆盖（后执行的覆盖先执行的）。当前不检测。

### 方案
在 `validateTable` 中增加静态冲突分析：

1. **重叠检测**：对每对启用行，判断条件是否存在非空交集。
   - 数值列：取两行在该列的条件区间，判断是否重叠（单值视为退化区间）。
   - 枚举列：取两行的取值集合，判断交集非空。
   - 列运算符不支持区间/枚举语义时（如 `>` 对枚举列），保守视为可能重叠。
2. **冲突分级**：
   - **错误**：两行条件完全一致（必然同时触发）。
   - **警告**：两行条件存在交集（可能同时触发），但不完全一致。
3. 警告不阻止发布，但在 API 返回和前端编辑器中明确提示。

当前实现已将数值边界、布尔值、有限枚举和字符串等于/排除转换为集合约束，可精确判断行对重叠，并通过有限原子候选搜索识别 `FIRST`/`PRIORITY` 下的单行或多行联合覆盖。缺口分析覆盖多维字段组合并给出具体输入见证；超过分析节点上限或遇到不支持的字符串关系运算时明确返回未知，不输出无法证明的结论。

### 范围
- 仅检测决策表内部行之间的冲突，不做跨规则/跨决策表的全局分析（后续迭代）。
- 空单元格（不限制）在区间分析中视为"全集"。

## 需求 3：默认行（otherwise）

### 现状
决策表所有行都是显式条件，没有 fallback。如果一组 facts 不满足任何启用行，所有输出字段保持输入值不变。

### 方案
- 决策表增加一个 `defaultRow` 标记：某一行可被标记为"默认行"。
- 默认行的条件列必须全部为空（即不带任何条件）；结果列正常填写。
- 生成 DRL 时，默认行的规则条件为：`not (row1 的条件 or row2 的条件 or ...)`，其中 row1..n 是其他启用的非默认行。
- 默认行内部 salience 设为低于同表所有显式行，资产级 priority 保持不变。
- 一个决策表最多一个默认行。
- 前端在表格底部固定一行"默认（otherwise）"输入区，与普通行视觉区分。

### 校验
- 标记为默认行的行，条件列必须全部为空。
- 最多一个默认行。
- 至少有一个非默认启用行时，默认行才有意义；没有任何非默认行时警告。

## 交付物

- `shared/rules.js`：无变化（原子规则层不感知决策表增强）。
- `shared/assets.js`：
  - 新增单元格解析函数 `parseConditionCell(field, operator, raw)` → 返回 DRL 条件片段数组。
  - `tableRules`：使用新解析函数，支持区间/枚举/默认行。
  - `validateTable`：增加区间/枚举校验、冲突检测、默认行校验。
- `server/index.js`：冲突警告随 validateTable 返回，API 透传到前端。
- `src/main.jsx`：
  - 单元格输入支持语法提示。
  - 冲突警告在编辑器顶部黄色提示条。
  - 默认行编辑区。
- `test/assets.test.js`：新增区间/枚举/冲突/默认行的测试用例。
