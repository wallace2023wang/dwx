# 企业规则平台产品需求说明

版本：0.13
状态：基线草案  
更新日期：2026-10-09

## 1. 产品目标

建设一套面向业务人员、规则开发人员、测试人员和运维人员的中文规则平台，覆盖规则设计、协作治理、发布部署和在线执行。Drools 是首个执行引擎，但管理模型不与 DRL 强绑定。

DWX 将规则设计、治理管理与生产执行划分为三个逻辑上独立的部分：

1. **规则设计中心（Rule Designer）**：结构化规则、决策表、规则集、业务词汇和测试用例的 Web 编辑体验。
2. **规则治理中心（Rule Team Server）**：资产仓库、版本、变更集、评审、审批、发布包、权限和审计。
3. **规则执行中心（Rule Execution Server，RES）**：接收不可变发布包，完成部署、版本路由、执行、监控和回滚。

核心原则：

- 业务用户编辑的是中文业务语义，不直接编辑 Drools 内部概念。
- 草稿、已发布版本、已部署版本是三个不同状态。
- 发布包不可变，任何内容变化都产生新版本和新校验和。
- 已发布规则集固定引用资产版本，历史决策必须能够重放。
- 生产执行不依赖设计中心或治理中心在线。
- 规则结构化模型是事实来源，DRL 是 Drools 适配器生成的构建产物。

## 2. 用户与职责

| 角色 | 主要职责 | 关键权限 |
|---|---|---|
| 业务规则作者 | 编写规则和决策表、维护业务说明 | 查看、编辑、提交评审 |
| 规则开发人员 | 维护业务对象模型、函数和高级规则 | 编辑技术资产、编译、诊断 |
| 测试人员 | 建立测试集、回归验证、影响分析 | 执行测试、确认测试门禁 |
| 审核人员 | 检查业务变化并批准变更集 | 审核、驳回、批准 |
| 发布经理 | 创建发布包并部署到目标环境 | 发布、部署、回滚 |
| 运维人员 | 管理 RES 集群、路由、容量和告警 | 环境管理、灰度、监控 |
| 审计人员 | 查询变更与执行证据 | 只读审计、报表导出 |

可配置策略应支持创建人与审核人分离、生产环境双人审批，以及按空间、项目、决策服务和资产授权。

## 3. 核心业务对象

```text
工作空间 Workspace
  └── 项目 Project
      └── 决策服务 Decision Service
          ├── 业务对象模型 BOM
          ├── 业务词汇 Vocabulary
          ├── 规则集 Rule Set
          │   ├── 向导式规则
          │   ├── 决策表
          │   └── 高级 DRL 规则
          ├── 规则集 Rule Flow
          └── 测试套件 Test Suite

变更集 Change Set
  └── 资产修订 Asset Revision

发布包 Release
  └── 可执行步骤、模型快照、引擎约束、校验和

部署 Deployment
  └── 环境、RES 集群、发布包、状态和流量策略
```

### 3.1 资产状态

```text
草稿 -> 待评审 -> 测试中 -> 待批准 -> 已批准 -> 已发布 -> 已归档
```

MVP 可以先保留“草稿/已发布”，但数据结构和 API 不得假设发布等于部署。

### 3.2 发布包状态

- `CREATED`：发布包已生成且不可修改。
- `VALIDATED`：已通过 Drools 编译和必需测试门禁。
- `DEPLOYED`：至少部署到一个 RES 环境。
- `RETIRED`：不允许新增部署，已有部署可按策略下线。

## 4. 功能需求

### 4.1 规则设计中心

#### 结构化规则

- 使用业务词汇配置条件和动作。
- 支持 AND/OR/NOT 条件组、嵌套条件、空值判断、集合操作和日期运算。
- 支持常量、枚举、参数、表达式和函数动作。
- 显示中文自然语言摘要和生成的 DRL 预览。
- 保存时做结构校验，试运行时做 Drools 编译校验。

#### 决策表

- 支持条件列、结果列、启停、复制、排序和批量填充。
- 支持数值区间、枚举多选、空单元格通配和默认行。
- 明确定义 `FIRST`、`ALL`、`PRIORITY`、`COLLECT` 命中策略。
- 检测重复行、重叠条件、不可达行和缺口。
- 支持 XLSX/CSV 导入导出，导入前预览差异和错误位置。
- 当前已交付决策表 XLSX/CSV 导入导出、列匹配校验和应用前行级差异预览；导入应用后仍通过正常保存与乐观锁流程持久化。
- 条件值支持“固定值 / 业务字段”切换；业务字段只列出同类型 input 字段并禁止自比较，动态阈值无需退化为高级 DRL。
- 测试时高亮命中行并显示结果覆盖顺序。

#### 规则集

- 支持开始、结束、规则集、决策表、条件网关、并行网关、聚合和子流程节点。
- 支持节点输入输出映射、异常分支、超时和逐节点调试。
- 第一阶段只实现短事务决策编排，不承载人工任务和长流程。
- 当前已交付串行多级排他网关首版：最多 4 个网关可插入任一公共步骤边界，每个网关分支按显示顺序判断并选择第一条匹配路径，可配置一个默认分支；分支执行后汇合回公共主线，再继续后续步骤或下一网关。
- 当前已交付无环有向图首版：分支可进入后续排他网关，多条路径可指向同一步骤完成汇合；保存、发布、设计期测试与 RES 执行使用同一节点和边语义。
- 当前已交付并行聚合首版：并行网关的 2–8 条分支从同一事实快照出发，全部汇入唯一配对聚合节点；不同字段和相同值变化自动合并，同一字段不同值返回结构化冲突，不使用隐式覆盖。
- 当前已交付节点输入输出映射：输入映射在节点执行前赋值，输出映射在节点执行后赋值，字段必须属于同一冻结 BOM 且类型一致；未配置时保持同名字段自动传递。
- 当前已交付设计期节点调试与路径断言：可运行到公共步骤、网关或分支步骤，失败时返回节点和现场轨迹，并可断言选中的排他分支。
- 当前已交付规则集依赖版本提示：已发布流程引用的规则或决策表升版后标记 `needsRepublish`；编辑器提示多个步骤写同一输出字段时后执行值会覆盖前值。可配置归并策略尚未交付。
- 当前已交付发布时内联的子流程首版：只允许引用同项目已发布规则集，最大嵌套深度 4，子流程升版后父规则集标记为需要重新发布，已发布父 Release 保持自包含。当前未交付嵌套并行和循环执行；高级图明确拒绝循环、孤立节点、不可达节点、无效目标引用和未汇入指定聚合节点的并行分支。
- 如需人工任务、定时器或补偿事务，后续集成 BPMN 引擎，而不是在规则集内重复实现。

#### 业务词汇与对象模型

- 技术字段映射中文名称、说明、数据类型、单位、枚举和输入控件。
- 支持字段分组、拼音搜索、废弃标记和兼容性校验。
- 模型变更时分析受影响规则、决策表、流程和测试。
- input 字段可标记执行时必填；缺失必填字段必须拒绝测试和 Release 执行，不得隐式补零或补 false。

### 4.2 规则治理中心

#### 资产仓库与版本

- 每次发布资产生成不可变版本；恢复历史版本只生成新草稿。
- 每次创建、保存和恢复草稿生成单调递增修订并保留快照；发布与归档也推进资产修订号，避免旧客户端继续写入。
- 资产生命周期独立区分活动、已废弃和已归档。废弃资产保留在包树和历史 Release 中但只读、不参与新执行制品，可记录原因和替代资产并恢复为草稿；归档资产默认隐藏且不参与包解析。
- 更新请求携带期望修订号。发生并发更新时返回 `409`、服务器当前修订号和当前快照，客户端不得自动覆盖本地未保存内容。
- 新建规则、决策表、规则集和事件流自动归创建人负责；OIDC 多人模式下只有负责人或管理员可修改、提交、归档、恢复或转交草稿。历史无负责人资产在首次编辑时自动认领，转交负责人会推进修订号并写入审计；本地模式保留单机兼容行为。
- 支持版本对比，结构化展示条件、动作、表格单元格和流程节点差异。
- 支持标签、分类、负责人、有效期和关联需求单。当前已交付负责人、标签和有效期首版；关联需求单仍待后续需求管理集成。
- 规则资产列表支持最多 100 项批量设置标签/有效期、转交负责人、移动规则包和归档。批量请求必须先完成全部目标的访问权限、负责人、审核锁和修订号校验，任一项失败时不得部分写入。
- 当前已交付跨项目资产目录，可检索规则、决策表、规则集、规则包和 BOM 中英文业务术语，并按项目、类型和状态筛选后定位到编辑或查看页面。
- 支持变更集聚合多个资产修订，作为评审和发布的最小单位。
- 当前已交付 Change Set 最小闭环：每个变更集最多固定 50 个规则、决策表或规则集修订，同时冻结最近发布基线、当前草稿和结构化字段差异。资产之后继续编辑不会修改既有评审证据。

#### 审核与门禁

- 支持提交、评审、驳回、批准和撤销。
- 发布门禁至少包括结构校验、Drools 编译、必需测试集通过和审批完成。
- 记录操作者、时间、意见、前后版本、测试报告和校验和。
- 当前已交付 `DRAFT -> SUBMITTED -> APPROVED/REJECTED` 状态流，驳回后可重新打开；空变更集和无实际差异的变更集不能提交。项目可配置 1/2 人批准、批准意见必填、禁止自审和允许审核角色；策略在提交时冻结，多人审核由最后一位不同审核人批准后发布。OIDC API 模式下身份来自验签 JWT，本机模式保留管理员自审能力。Release 强制关联批准变更集尚未交付。
- 当前已交付追加写审计查询，覆盖资产、BOM、测试套件、Release 和 Change Set 核心动作；业务 API 不提供审计更新或删除接口。

#### 身份与权限

- 管理 API 支持 `local` 和 `oidc` 两种模式；`oidc` 模式必须校验 issuer、audience、签名和有效期，不能信任客户端自行声明的用户头。
- 第一阶段角色为查看者、规则作者、评审人、发布管理员和系统管理员，分别控制查看、资产编辑、变更评审、Release 创建/部署和全部操作。
- 当前已交付 API 侧 OIDC discovery、JWKS 验签、标准/Keycloak 角色提取、粗粒度路由 RBAC 和当前会话查询。
- 当前已交付浏览器 Authorization Code + PKCE/BFF 登录与退出、策略式项目/资产授权和用户目录 CRUD；自定义角色模型、工作空间级多租户和服务账号管理尚未交付。

#### 测试与影响分析

- 支持单案例、参数化案例、表格批量案例和生产样本回放。
- 支持期望输出、期望命中规则和期望流程路径断言。
- 当前已交付项目隔离的已发布规则、决策表和规则集测试套件：每套最多 200 个案例，可创建、编辑、归档、启停案例、运行单套件和全量回归，报告固定记录目标资产版本、逐案例断言、失败原因和耗时。
- 当前已交付参数化数据集：案例可保留基础输入并配置最多 100 个命名参数行，参数覆盖值由 BOM 类型控件录入；单套件展开后最多执行 1000 次，报告保留场景和参数行标识。
- 当前已交付必需套件发布门禁：创建 Release 时实时重跑同一目标的所有必需套件，任一失败则拒绝生成 Release；历史成功报告不能替代当前版本重跑。
- 当前已交付新旧已发布版本并行对比，按未变化、有变化、已改善和有回归分类，并统计待确认样本；对比报告进入历史但不替换 Release 门禁使用的最近常规运行。
- 当前已交付规则、启用的决策表行和规则集分支路径覆盖率，报告展示覆盖比例及未覆盖项。
- 当前报告展示规范化输入和未提供字段；Release 门禁失败响应提供最小失败用例与断言摘要。

#### 发布与部署

- 从已批准或当前已发布资产生成不可变 Release。
- Release 包含决策服务标识、语义版本、资产版本、步骤快照、DRL、模型版本、Drools 兼容版本和 SHA-256。
- 发布不自动改变生产流量；部署是独立授权动作。
- 可查看每个环境正在运行的 Release、部署历史和回滚目标。
- 当前已交付项目级 Release 构建、local 部署和执行代理；Release 只读取本项目的已发布资产、BOM 和必需测试套件，跨项目资产、套件与 Release ID 均不可访问。
- 当前 Release 响应标记其是否为同一 decisionService 的最新版本；创建真实项目 Release 时可自动补齐项目命名空间。
- 同一决策服务允许多个版本保持已部署，但每个 `decisionService + environment` 最多只有一个当前生效版本。
- 当前已交付 local 环境的激活、回退和卸载；生效版本禁止直接卸载，避免稳定入口无意中断。
- 项目提供不含 Release ID 的稳定执行入口，调用方不需要在版本激活或回退后修改地址。
- 发布页必须区分“已构建、已部署、当前生效、已停用”，不能把所有历史部署统一显示为“运行中”。

#### 项目报告

- 提供项目级只读知识资产报告，汇总项目概览、BOM 资产、规则与决策表清单、规则集拓扑、测试矩阵、覆盖率、Release 和部署历史。
- 支持在报告页面查看并下载自包含 HTML；浏览器打印可保存为 PDF，不要求服务端安装 PDF 渲染器。
- 报告必须遵守项目与资产授权，优先展示已发布规则集快照；没有对应数据时显示空态，不伪造统计结果。

### 4.3 规则执行中心（RES）

- Release 步骤统一支持规则、决策表和规则组；规则组在发布时冻结完整合并 DRL，运行期不回查 Team Server。
- 执行接口支持可选的受限多轮收敛、显式 output 到 input 反馈映射和逐轮轨迹，循环有硬上限。
- 必填输入缺失时明确拒绝；新发布产物的可选数字和 Boolean 字段保留 `null`，可区分未传与显式 `0`/`false`。

- 提供独立进程和镜像，不读取 Team Server 草稿存储。
- 通过管理接口部署已签名或带校验和的 Release。
- 同一决策服务支持多个并存版本，并能按显式版本调用。
- 执行请求必须指定决策服务；生产模式下禁止上传任意 DRL 后直接执行。
- 返回业务输出、命中规则、步骤轨迹、执行耗时、Release ID 和关联 ID。
- 部署幂等：相同 Release ID 和校验和重复部署成功；内容不同则拒绝。
- 支持健康检查、就绪检查、部署清单和版本下线。
- 已支持 local 环境默认生效版本和稳定服务路由；后续支持按租户路由、百分比灰度、超时、并发限制和熔断。
- 执行日志默认不持久化完整敏感输入，只记录可配置摘要和技术指标。
- CEP 命中按 `Release + statement + output event type + correlation key` 形成告警实例；首次命中为 `ACTIVE`，人工确认迁移为 `ACKED`，超过配置的消退窗口自动迁移为 `CLEARED`，已清除实例再次命中时以同一实例 ID 回到 `ACTIVE`。
- ACK 只记录处理人和处理时间，不停止监控或重置自动消退计时；已清除告警不能确认。告警状态由 CEP Runtime 持有并在重启后恢复，Team Server 仅按 Release 代理查询和确认并记录审计，生产事件调用不依赖 Team Server。

## 5. 非功能需求

### 安全

- 管理接口和执行接口分离鉴权。
- 任意 DRL 上传仅允许在受信任构建区，RES 只接受治理中心生成的发布包。
- 发布包校验和必须在 Team Server 和 RES 两侧验证。
- 审计日志追加写，业务操作不得覆盖历史记录。
- 支持字段级脱敏、日志留存期限和密钥外置。

### 可靠性

- RES 重启后能够恢复已部署 Release。
- 单个 Release 编译或执行失败不得影响其他版本。
- 部署先完成编译和预热，再进入可路由状态。
- 回滚只改变路由，不重新生成历史制品。

### 性能目标

- 单规则集热执行 P95 小于 50ms，不含网络和外部服务。
- RES 部署后首次执行不得触发重复编译。
- Team Server 的资产列表和版本查询 P95 小于 500ms。
- 批量测试和生产执行使用独立资源池。

### 容量与规模化基线

平台必须面向大型规则库，不能把“全部资产一次加载到浏览器”和“同步编译整个规则包”作为长期架构。需要分别验证单项目资产规模、单包成员规模和单张决策表展开后的规则规模。

目标容量如下；这些数值是后续规模化专项的设计与压测目标，不表示当前版本已经达到：

| 维度 | 目标容量 |
|---|---:|
| 单项目规则资产总数 | 10,000 |
| 单规则包已发布成员 | 5,000 |
| 单张决策表行数 | 10,000 |
| 单个 Rule Group 展开规则数 | 5,000 |
| 资产列表与版本查询 | P95 < 500ms |
| 普通资产搜索交互 | P95 < 300ms |

规模化演进必须满足以下原则：

- 资产、版本、审计、报告和 Rule Group 成员接口采用服务端分页、排序和搜索；数据库查询必须在分页前过滤，不允许先取出全项目数据再分页。
- 前端资产列表、Rule Group 成员预览和大型决策表使用虚拟滚动或分块渲染，不一次创建数千个 DOM 节点。
- 规则集详情只返回规则包摘要和成员数量；完整成员清单按需分页获取，避免与 `availableAssets` 重复传输。
- Rule Group 和大型决策表编译使用后台任务，提供排队、进度、取消、超时和可定位的失败日志；浏览器不负责生成组合 DRL。
- PostgreSQL 是大规模生产部署的默认元数据存储。组合 DRL、预编译制品和大型发布快照进入制品/对象存储，数据库保存 manifest、fingerprint、校验和及制品地址。
- RES 部署阶段完成编译和预热，并按 Release 版本缓存有界 KieBase；业务请求不得触发重新编译。
- 每次容量相关改动至少执行 1,000、5,000、10,000 三档基准，记录 API 延迟、前端可交互时间、编译时间、制品大小、JVM 峰值内存、RES 启动时间和热执行 P95/P99。
- 达到容量上限时必须明确拒绝并返回可操作的诊断，不允许静默截断 Rule Group 成员、决策表行或发布内容。

当前版本仍存在全量项目摘要、完整 Rule Group 成员传输、非虚拟化列表以及同步组合 DRL 编译等限制，适合功能验证和中小规模规则库。是否达到上述目标必须以可复现的基准报告为准，不能仅依据 Drools 理论容量判断。

### 可观测性

- 指标至少包括请求数、成功率、P50/P95/P99、规则命中数、执行上限、部署状态和编译耗时。
- 日志关联 `requestId`、`decisionService`、`releaseId` 和 `deploymentId`。
- 支持 OpenTelemetry 接入，指标名称不包含高基数业务字段。

## 6. MVP 验收范围

当前里程碑聚焦三个产品之间的第一条真实主链：

1. 设计中心可以发布规则、决策表、线性规则集和带串行多级排他网关的规则集不可变资产版本。
2. Team Server 可以从已发布资产创建不可变 Release，并计算稳定校验和。
3. Team Server 可以把 Release 部署到独立 RES。
4. RES 可以持久化、编译并按 Release ID 执行；线性规则集按顺序传递输出并应用节点字段映射，分支规则集在每个网关选择首条匹配分支或默认分支，执行后汇合回公共主线。
5. 页面可以查看 Release、部署状态并发起测试执行。
6. Release 冻结分支条件、步骤归属和节点字段映射，Team Server 与 RES 返回一致的网关轨迹、选中路径和映射轨迹。
7. 原有设计时 `/compile`、`/test` 与 RES 生产执行接口保持隔离。
8. 每个项目的测试套件可对本项目三类已发布资产执行输出、命中规则和流程路径断言；必需套件失败会阻止同项目 Release，门禁报告可在页面查看。

9. Team Server 可使用 PostgreSQL 持久化全部现有业务对象；JSON 数据可一次性原子导入，重复导入不会覆盖数据库。
10. 规则、决策表、规则集、测试套件和 BOM 具备乐观锁；资产草稿修订历史在服务重启后可恢复。
11. 规则、决策表、规则集和 CEP 事件流发生并发保存冲突时，前端基于开始编辑的草稿、本地草稿和服务器最新草稿做字段级三方合并；非重叠修改自动保存，重叠修改必须由用户逐项选择，禁止静默覆盖。
12. 规则、决策表、规则集和 CEP 事件流编辑页展示同资产在线成员及查看/编辑状态；服务端修订变化须在不覆盖本地草稿的前提下主动提示，保存继续使用字段级三方合并。
13. CEP 高级 EPL 编辑器支持同一语句的实时共同编辑：文本更新、在线状态和光标位置即时推送；并发文本帧必须按序列确认，过期序列禁止静默覆盖。该能力不替代保存时的资产修订校验。
14. Change Set 可以固定多个资产修订、展示结构化差异并完成提交、批准、驳回、重新打开；核心动作可以在审计日志中查询。
15. 每个服务端项目可以独立构建、查询、部署和执行 Release；Release、部署回执、审计和 PostgreSQL/JSON 数据互不串项目。
16. 测试套件支持 BOM 驱动的参数行、两个已发布版本的行为对比，以及规则、决策表行和规则集路径覆盖率；对比历史不替换 Release 门禁使用的常规运行报告。

本里程碑不包含可配置多级审批、Release 强制绑定批准 Change Set、结构化 BAL/决策表/流程图的字符流共同编辑、跨 Team Server 实例协作消息共享、集群路由一致性、灰度路由、嵌套并行与 BPMN。高级 EPL 字符输入即时共同编辑与光标同步、串行多级排他网关、无环有向图、并行聚合、草稿所有权、结构化字段合并、在线成员与修订通知首版已经交付。

## 7. CEP 引擎选型与 Esper 替换评估建议

> 2026-10-09 补充。Esper 8.8.0 采用 GPLv2 / 商业双授权：本地研发、产品验证与客户 Demo 不构成对外分发，GPLv2 分发义务暂不触发。一旦对外分发或商业交付立项，必须在“采购 Esper 商业授权”与“替换引擎”之间完成决策，本节结论作为该决策的输入。

### 7.1 替换约束

CEP 页面以 EPL 为唯一作者语言：向导模板现场生成 EPL 文本，高级模式直接编辑 EPL，编译诊断按 EPL 位置回映，保存时校验“模板参数重算结果与存储 EPL 一致”。页面不改变意味着必须保留 EPL 作为作者语言，任何替换都要在后端增加“EPL → 目标引擎”的编译适配层；没有任何其他开源引擎原生接受 EPL。

### 7.2 两个主要建议

**建议一：若选择开源替换，首选 Siddhi 5.1+（Apache-2.0），备选统一到 Drools 10.x。**

- Siddhi 与 EPL 的语言形态最接近：原生支持 `not` 缺席检测、`{n}` 连续计数、`within` 超时、`every`/`->` 时序；`#window.time` / `#window.timeBatch` 对应 `#time` / `#time_batch`；`partition with` 对应 `partition by`；timer source 提供周期触发。
- 部署形态一致：可嵌入 JVM 进程内运行，与现有 CEP 服务的 compile / deploy / ingest / listen 四类引擎调用一一对应；fired/cleared 告警状态机、metrics、OpenAPI 和部署持久化均为引擎无关的服务端实现，不受替换影响。
- 备选 Drools 与规则侧同引擎，可裁掉独立 CEP 引擎与镜像；代价是 EPL → DRL 翻译工作量最大，per-key 动态计时器（缺席检测）表达受限，且 Drools 10.x 事件处理特性的维护状态需要先验证。
- 已排除：Flink / Flink SQL（集群化运维与当前嵌入式部署模型差异过大，缺席与 per-key 计时器需落到维护度低的 FlinkCEP）；流式数据库（无 pattern / 缺席语义）；自研引擎（长期维护成本高）。

**建议二：需要任意高级 EPL 无损等价时，选择采购 Esper 商业授权，而不是移植任意 EPL 语义。**

高级模式允许任意 EPL，开源引擎只能覆盖冻结的受支持子集；若要求“任意 EPL 完全等价”，迁移成本与长期语义对齐风险高于授权费用。仅内部使用的场景保持现状即可，以上两条建议均只作为对外分发立项前的决策输入。

### 7.3 若选择替换的落地路径

1. 盘点高级模式语句的真实使用面，冻结《EPL 兼容受支持子集》（覆盖现有全部向导模板生成的语句形态 + 高级白名单语法）。
2. 在 CEP 服务抽取引擎适配接口（compile / deploy / ingest / listen），Esper 与目标引擎双实现，部署增加引擎标记，支持同一 Release 并行回归。
3. 以现有模板基线（`test/cep-templates.test.js`、`test/fixtures/cep-template-baseline.json`）以及处理时间、fired/cleared、webhook、OpenAPI、metrics 契约做验收；通过后切换默认引擎并保留回退开关。
4. 编译诊断按 EPL 位置回映：模板语句按结构精确映射，高级语句至少保证行级定位。

### 7.4 替换专项 POC 风险清单

- 连续计数的“不满足即重置、不重叠计数”语义与 Esper `match_recognize ... after match skip past last row` 的一致性（粮库/氮气场景实际依赖）。
- `within` 超时取消本次匹配的语义对齐。
- `timer:*` 使用处理时间而非事件时间回放的语义保持。
- per-key 分区（`partition with`）在窗口聚合与 pattern 下与现有 `groupField` 行为的一致性。

## 8. DWX 产品能力差距分析（P0–P2）

> 2026-10-09 补充。以下能力差距作为后续需求立项输入；本节范围限定 P0–P2，不改变现有关键路径。

### 8.1 P0：结构化规则资产硬缺口

| 差距 | 目标能力 | 现状与影响 |
|---|---|---|
| 决策树（Decision Tree） | Rule Designer 业务作者构件 | 已交付首版：业务用户可编辑固定是/否分支树，每条根到叶路径编译为互斥规则并进入审批、测试、规则集和 Release 冻结；首版不支持任意多分支、统计学习树或不安全取反运算符 |
| 计分卡（Scorecard） | 评分/风控场景主力构件 | 已交付首版：支持初始分、输入特征顺序分箱、唯一默认分箱、总分数值输出和连续结果分段；编译为共享 activation group 的确定性 Drools 规则，并进入审批、测试、规则集和 Release 冻结链路 |
| 规则模板（Rule Template） | 参数化规则批量派生 | 已交付首版：支持 1–20 个强类型参数、条件/动作参数槽和 1–200 个可启停实例；启用实例在编译和发布时展开为普通 BAL 规则，已进入 BOM 影响分析、审批、测试覆盖率、Rule Group/规则集和 Release checksum 冻结链路；首版不支持嵌套条件树、动作表达式或项目变量参数化 |
| DWX 资产包导入导出 | 项目间结构化资产迁移 | 已交付首版：版本化 DWX Asset Package 支持服务端预览、BOM/结构校验、同名冲突检查、`sourceId` 幂等导入，以及 Project/Ruleset/Package 映射；五类结构化规则资产导入为草稿，纯 Rule Group 规则集可无损导出和重新导入；无法无损表示的复杂规则集在导出结果中明确警告并跳过 |

### 8.2 P1：规则表达力与执行语义

| 差距 | 目标能力 | 现状与影响 |
|---|---|---|
| 嵌套条件组 | IRL/BAL 任意嵌套布尔 | 已交付 5 层内结构化 AND/OR 条件树，可表达 `(A∧B)∨(C∧D)`；NOT 与更高级条件元素继续沿用现有量词/高级表达式能力 |
| 表达式与函数动作 | IRL 算术与函数调用 | 已交付数值字段/变量、四则运算和 `min/max/round/abs` 白名单表达式，结构化 AST 随发布冻结 |
| BOM 类模型、方法与动态域 | BOM/XOM、verbalization、dynamic domain | 已交付事实类型分组、可复用安全数值业务方法和 BOM 版本化动态枚举域；任意 Java/XOM 方法体、继承层次和外部数据源动态域仍未支持 |
| Decision Warehouse | RES 执行轨迹持久化与查询 | 执行 trace 仅随响应返回、不落库；无法按调用方/规则/时间反查历史决策，“历史决策可重放”只覆盖输入冻结的一半 |
| 同字段多输出归并策略 | 多命中结果归并 | 规则集/决策表/Rule Group 同字段写入为确定性后写覆盖，曾造成实际误判；归并策略仍在最低优先级待办 |

### 8.3 P2：集成与运行

| 差距 | 目标能力 | 现状与影响 |
|---|---|---|
| 无 HTDS 等价物 | 透明决策服务（类型化端点、XSD/WSDL） | 仅提供通用 `{facts}` 执行接口；无按决策服务生成的类型化契约，外部集成成本高 |
| CEP 仅 HTTP 接入 | Decision Server Events（Kafka/MQ/JMS） | CEP Runtime 只有 `/events/{id}`、`/execute`、`/webhook`，无消息中间件接入 |
| 容量未验证 | 大规模规则库 | 全量项目摘要、Rule Group 成员全量传输、非虚拟化列表、同步组合编译为现状限制；10,000 资产 / 10,000 表行目标没有任何基准报告 |
| Esper 授权与替换 | —（本项目特有） | 评估结论与两条主要建议见第 7 章，不重复展开 |

### 8.4 建议

- P0 四项均已交付首版；后续资产迁移工作聚焦 DWX 资产包的复杂规则集无损表示、选择性导出和版本兼容，不再阻塞结构化资产迁入。
- P1 表达力三项（嵌套条件组、表达式动作、BOM 方法）合并为“规则语言 v2”专项设计，统一改动生成器、DRL 冻结与 checksum 语义，避免分次改动反复影响已发布资产。
- P2 容量未验证项并入现有容量专项按 1k/5k/10k 档位补基准；CEP 消息接入随 CEP 生产化需求触发立项。
